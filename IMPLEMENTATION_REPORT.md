**Error Handling:**
- 401 Unauthorized: If not authenticated (redirects to OAuth2 authorization)
- 200 OK with empty array: If no activities logged yet
- All errors gracefully degrade to fallback recommendations

## 5. RECOMMENDATION GENERATION FLOW

### LLM-First with Graceful Fallback

```
User calls GET /api/recommendations
    ↓
SecurityService.getCurrentUser() → Extract authenticated user
    ↓
ActivityLogRepository.getTopEmissionActivities(userId, last30days) → Fetch top 3
    ↓
IF activities.isEmpty() → Return empty list
    ↓
IF llmRecommendationService.isAvailable() → Check: enabled + API key + URL
    ├─ YES: Try LLM
    │   ├─ RecommendationPromptBuilder.buildPrompt()
    │   ├─ RestTemplate POST to OpenAI
    │   ├─ Parse JSON response
    │   ├─ Validate each recommendation
    │   │   ├─ Activity type in original list?
    │   │   ├─ Priority in {HIGH, MEDIUM, LOW}?
    │   │   ├─ Tip ≤ 200 chars?
    │   │   └─ Potential saving 0-100%?
    │   ├─ On success → Cache results + Return with generatedBy="LLM"
    │   └─ On error (malformed JSON, timeout, invalid) → Catch exception
    │
    └─ NO or ERROR: Use Fallback
        ├─ RecommendationCatalog.getMapping(activityType)
        ├─ Generate rule-based recommendations
        └─ Return with generatedBy="FALLBACK"
    ↓
Cache result per user username
    ↓
Return List<RecommendationResponse> (max 3 items)
```

### Cache Invalidation
- Triggered: When new activity is logged via `ActivityLoggingServiceImpl.logActivity()`
- Method: `RecommendationServiceImpl.evictRecommendationCache()`
- Scope: Per authenticated user's username
- Effect: Next `getRecommendations()` call generates fresh recommendations

## 6. SECURITY FEATURES

### Data Protection
- **No User PII Sent to LLM:** Only activityType, category, totalEmissions
- **No API Key Logging:** Sensitive values never logged
- **No Response Body Logging:** Full responses not logged to avoid data exposure
- **Prompt Security:** Explicit instructions preventing personal info extraction

### API Authentication
- `@PreAuthorize("isAuthenticated()")` enforces Spring Security
- OAuth2 integration with Google provider
- JWT token validation
- SecurityContextHolder isolates user data per request

### Timeout Protection
- RestTemplate configured with 30-second timeout
- Prevents hanging requests
- Automatic fallback on timeout

### Response Validation
- Activity type validation (must exist in original list)
- Priority validation (HIGH/MEDIUM/LOW only)
- Tip length validation (max 200 chars)
- Potential saving validation (0-100% range)
- Invalid values rejected or sanitized

### LLM Prompt Constraints (in prompt text)
```
- No personal information (username, email, password, ID)
- No medical claims
- No legal claims
- No financial claims
- JSON format only (no markdown)
- Max 3 recommendations enforced
- Exact schema required
```

## 7. FALLBACK MECHANISM

### When Fallback is Used
1. LLM disabled (`llm.enabled=false`)
2. API key missing (`LLM_API_KEY` not set)
3. API timeout (>30 seconds)
4. API returns non-200 status
5. Malformed JSON response
6. Activity type not in original list
7. Invalid recommendation fields
8. Network connectivity issue

### Fallback Implementation
- Uses `RecommendationCatalog` class (pre-existing rule-based mappings)
- Per activity type, has predefined tips and targets
- Returns same `RecommendationResponse` structure
- Sets `generatedBy="FALLBACK"`
- Ensures recommendations always available to users

## 14. KNOWN LIMITATIONS & FUTURE ENHANCEMENTS

### Current Limitations
1. **Single activity type per recommendation:** LLM generates one tip per activity
2. **Fixed 30-second timeout:** Not configurable via properties
3. **No recommendation feedback:** Users can't rate/improve recommendations
4. **Cache TTL fixed:** Uses Spring default cache expiration

### Future Enhancements
1. **User feedback loop:** Like/dislike recommendations to tune LLM
2. **Historical tracking:** Store generated recommendations for analytics
3. **Batch optimization:** Generate for multiple users in single request
4. **Multi-language support:** Localize recommendations
5. **Custom LLM providers:** Support Anthropic, Google AI Studio, etc.
6. **A/B testing:** Compare LLM vs. fallback effectiveness
